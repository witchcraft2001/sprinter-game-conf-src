# GAMEDIAG для game K50

Сборка: `make -C diagnostics` из корня репозитория. Нужны sjasmplus и Python 3.
Получается небольшой DSS EXE с 56 нумерованными клетками 8×8 и различимыми
первыми/последними строками и столбцами. Собран локально; на плате не запускался.

Запустите `GAMEDIAG.EXE` из DSS со стандартной работающей K50-конфигурацией.
В том же каталоге должен находиться **game** `K50.ACX`, прошедший проверки
`make_game_k50.bat`. Программа проверяет DSS >=1.70 build 998, размер ACX
1…65536 и K50 prefix, читает ACX в нужное число DSS страниц (1…4) и вызывает
BIOS AcexSetUpNow. Требования к BIOS и восстановлению — в
[GAME_K50.md](../docs/GAME_K50.md). Свободные хвосты страниц заполняются FF.
Полнота чтения проверяется по итоговой позиции файла (DSS.Move_FP), без
предположений о DE после DSS.Read; проверяется carry AcexSetUpNow. Буфер списка
страниц вмещает FF terminator BIOS. Диагностика не заменяет проверку roundtrip
и отчёта сборки.

`uv run --with z80 python diagnostics/simulate_game_diag.py` исполняет собранный
EXE на Z80 с моделями BIOS/DSS/VRAM; 23 сценария прошли локально.

После reconfiguration восстанавливается HOLD (CBh) из CMOS ScreenPosition
через BIOS F6/F8. В F6 передаётся **D=1Fh**, как задаёт ScreenPosition в
`sprinter_bios/Shared_Includes/constants/SP2000.inc`; D=0 читает секунды RTC.
Ранее скопированный из TITDREV адрес 0 был ошибкой и исправлен.
Это нужно для сравнения положения изображения
со стандартной конфигурацией. При ошибке чтения CMOS остаётся положение после
reset; ошибка записи HOLD завершает диагностику. Сам растр FPGA этот код не меняет.

После reconfiguration программа не вызывает DSS video API. Она напрямую пишет
VRAM и palette через существующие PAGE3/PORT_Y, опрашивает ZX keyboard matrix с
отключёнными CPU-прерываниями. Аппаратный interrupt проверяется моделью и TITD,
а не доставкой прерывания CPU этой программы.

Инициализируются также два дополнительных столбца и две строки дескрипторов
за физическим растром (всего 58×42 на каждой странице). Скролл может выбрать их
без оборачивания по 448/320; там задаётся border/blank вместо случайных данных.

- `1`: X scroll +1, с переходом 15→0.
- `2`: Y scroll +1, с переходом 15→0.
- `3`: переключение страницы; номера клеток на второй странице идут в обратном порядке.
- `4`: нулевой scroll.
- `Q`: hard reset через BIOS, возврат к стандартной ROM-конфигурации.

Каждое нажатие применяется один раз до отпускания клавиши. Управляющие клетки
размещены в невидимом столбце 53 всех строк. Отдельные строки используют разные
палитры; низ растра содержит blank/interrupt descriptors. Проверяйте все 16×16
смещений, особенно 7→8 и 15→0, обе страницы, швы клеток и стабильность синхронизации.
Обновление таблиц идёт без ожидания VBlank: кратковременный разрыв во время
нажатия возможен; оценивать нужно установившееся изображение после отпускания.

Диагностика завершает работу перезагрузкой, без восстановления прежнего текста
DSS. Для проверки мягкого выхода и повторного запуска используйте TITDREV.
Не заменяйте этим ACX стандартный образ ROM. Если BIOS reset не сработает,
выключите/включите питание либо восстановите сохранённый стандартный SOF через JTAG.
