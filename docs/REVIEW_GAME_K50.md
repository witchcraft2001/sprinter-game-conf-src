# Кодревью GAME_K50 — 10 октября 2026

План выполнен в части исходников, инструментов и локальных проверок. После
первого ревью пользователь исправил ошибки компиляции и сообщил об успешном
запуске game на K50: скролл работает, но есть мигающие артефакты, в том числе
на статике; VRAM — IS61C1024-15N. Приёмка не завершена: нет переданного fitting
report, проверки CLK42/SRAM/DAC и подтверждения работы без артефактов.
Текущую правку скролла ещё нужно пересобрать под Windows и испытать.
Последнее наблюдение пользователя относится к предпоследней сборке;
точная ревизия испытанного ACX не установлена.

## Повторное ревью: положение изображения и граница скролла

Пользователь уточнил: горизонтального смещения **нет**, вниз — примерно
на **8 пикселей**, проверялась предпоследняя сборка. Это заменяет прежнее
наблюдение о смещении влево и вниз на 16 пикселей. Результат проверки замечаний:

| Замечание | Вывод и действие |
|---|---|
| Горизонтальное начало на знакоместо раньше штатного | Снято после уточнения пользователя. Поправка −8 отменена в TDF, модели и тестах; сохранён prefetch `physical_x+1 mod 448`. Прежний вывод только по адресу/WR_MODE не учитывал весь штатный RGB-тракт. Тест проверяет формат дескриптора и сохранение game-привязки, а не доказывает положение на мониторе |
| Control меняет сетку внутри помеченной клетки | Подтверждено первичным комментарием `games/game_conf/tests/RELOAD.ASZ:394`. MODE3 сохраняется при входе, применяется однократно при выдаче последнего байта клетки; следующий запрос получает новое смещение через bypass. Проверены все 256 новых значений поверх ненулевого старого, без шва внутри клетки, в том числе при перезаписи MODE3 CPU |
| Вертикальный сдвиг примерно на 8 строк | CTV, COPY_SINC_V и preload сохранены; произвольная поправка Y не внесена. Найдена ошибка адреса CMOS в доступном TITDREV: D=0 читает секунды, ScreenPosition в доступном BIOS — 1Fh. Исправлен аналогичный код GAMEDIAG и его модель CMOS; внешний TITD не изменён. Возможная причина положения, но связь с испытанными BIOS/EXE и ровно 8 строками ещё не установлена |
| WR_PIC/WR_COL/WR_MODE, X_MODE_BOND, G_VALID | Неиспользуемые внутренние strobes/узел удалены; внешний WR_COL остаётся TSN_W3. G_VALID удалён: реальный descriptor request не равен нулевому G_LAST |
| MODE0[4]/[5] | Ограничение 320-пиксельной байтовой графики зафиксировано: отдельные 640/text режимы не реализованы |
| Старый make_k50.bat перестал выдавать STREAM.BIN для BIOS | Исправлено: legacy-вход публикует только проверенный несжатый STANDARD_K50 в прежний путь. Game-публикация туда запрещена; негативные тесты сохраняют старый файл при ошибке валидации |
| Путь MAX+plus II отличается | Сохранён рабочий вложенный путь пользователя и добавлен fallback на исходный путь. MAXPLUS2_EXE имеет приоритет |
| LOCATION/ignored assignments | Проверить по новому fitting report. Pins и общий write-floorplan сохранены; удалять все назначения или считать их корректными без отчёта нельзя |

Расчёт из ревью подтверждает пользу двух периодов, но не заменяет post-fit
проверку. Для FPGA→SRAM→FPGA нужно учитывать реальные пути VLA→VA и VD→MODE/
G_COLOR, включая mux банка и routing. Table 49 ACEX описывает внешние параметры
в своих условиях; VD — двунаправленные выводы (также Table 50). Значения 7,3/3,9
нс нельзя автоматически приравнивать к задержкам любых внутренних регистров
этого проекта. [Даташит Altera ACEX 1K](https://datasheet4u.com/pdf-down/E/P/1/EP1K10-Altera.pdf).

Для палитры бюджет **не** равен просто `23,81 - tAA` на setup 74HC374:
нужно прибавить задержку WR_COL до clock-входа RGB-регистра и вычесть задержки
VA до SRAM, SRAM→RGB и setup. Для hold проверяется противоположный край задержек.
RC-цепь на WR_COL влияет на обе проверки. После предыдущего патча положительный
фронт CT=0 сохранён, но строб CT=4 удалён: частота/скважность отличаются от штатных.
Кроме того, fitting может изменить задержки даже неизменного write-тракта.
Поэтому «штатная работает ⇒ game не добавляет рисков» — слишком сильный вывод.
Свежая стандартная сборка остаётся нужным контрольным экспериментом.
`altera/acex/orig/readme.txt` действительно выделяет 3.04 с таймингами Alliance;
совпадение текущего write-тракта с исправлениями 3.04 не подтверждено.

Общие multicycle-исключения не добавлены. Между физическим продвижением CT=6
и prefetch CT=2 **три** периода (6→0→1→2), а не два. MODE→первый pixel VLA имеет
два периода (5→6→0). Новый pending/bypass и DIR_PORT имеют свои условия
стабильности; особенно нельзя приписывать синхронную двухтактность CPU-регистрам
страницы. Если Fmax ниже 42 МГц, сначала нужен разбор конкретных launch/capture
путей и enable, включая hold, а не глобальное ослабление constraints.

## Замечания и исправления

| Приоритет | Найдено | Исправление / статус |
|---|---|---|
| Высокий | Game захватывал цвет после одного CLK42 при двух слотах адреса; дескриптор также получал один CLK42. В задержку 23,81 нс должны войти SRAM и оба пути FPGA | Цвет захватывается CT=2, дескриптор выдаётся CT=2/удерживается CT=4/захватывается CT=5: оба чтения получают 47,62 нс. Один внешний RGB-строб CT=0 после палитры CT=6. Модель с 30 нс проходит; ранние захваты и лишний RGB-строб отвергаются. Плата ожидает повторной проверки |
| Высокий | BIOS GetMemBlkPages пишет список **и FF terminator**, четырёхбайтный буфер портил следующий scroll | Буфер 256 байт; проверка B; Z80-тест списка и начального scroll |
| Высокий | Диагностика принимала короткий DSS.Read с carry=0 и не проверяла ошибку AcexSetUpNow | Проверка итоговой позиции файла через DSS.Move_FP, carry BIOS; DE после Read не используется, в тестах он произвольный |
| Высокий | Диагностика передавала BIOS четыре страницы при любом размере файла | Выделяются ровно ceil(size/16384) страниц; хвост FF; проверены размеры 7…65536 |
| Средний | Диагностика требовала первый zero-run строго 01, хотя он может продолжать нули за заголовком | Принимается любой ненулевой счётчик, файл короче 7 байт отвергается; count 2/255 и усечение проверены |
| Средний | OR старших битов адреса X превращал диагностический blank FC в interrupt FD | Адресные биты добавляются только обычной графике; проверены все карты |
| Высокий | Удаление всех LC/EAB в стандартном staging изменяло контрольную конфигурацию и write delays | Размещения сохранены, pins сохранены; аудит требует Windows fitting review |
| Средний | PowerShell 5.1 был дополнительной зависимостью, упаковочные проверки здесь не исполнялись | Штатный cmd + WSH/JScript; один core исполняется cscript/Node; 20 тестов прошли |
| Высокий | Самописная модель не проверяла выражения нового TDF | Ограниченный интерпретатор фактического read pipeline; обе страницы/полный растр, scroll 0…15, банки/палитры/спецрежимы; четыре мутации выявляются |
| Высокий | Формат ACX выводился из названия, без выполнения загрузчика | Выполнены TITDREV startup и BIOS header check/bit sender; zero-packer поток с offset 0, K50 signature, страницы/размеры проверены |
| Средний, внешний код | TITDREV использует JP NZ после ADD HL,BC, сохраняющего Z | Необязательный tools/titdrev_acx.patch исправляет только FF tail. Не является требованием K50; штатный loader тоже прошёл проверки, внешний репозиторий не изменён |

Замечание о необходимости сравнивать возвращённый `DE` DSS.Read было ошибкой
ревью и снято после уточнения контракта пользователем. Такая проверка удалена
из патча и диагностики; тесты больше не обещают счётчик в DE. Стабильная загрузка
K30 сама по себе не требует переделки загрузчика ради K50. Применять необязательный
FF-tail патч к TITD перед первым испытанием K50 не требуется.

- После повторного ревью: `python3 -m unittest discover -s tests -v`: 22 теста
  успешно. Дополнительно проверяется перезапись pending MODE3.
- `node tests/test_k50_build.js`: 21 проверка успешно; WSH COM/cmd не покрыты.
- `make -C diagnostics`: 0 ошибок и предупреждений, GAMEDIAG.EXE собран.
- `uv run --with z80 python diagnostics/simulate_game_diag.py`: 23 сценария успешно.
- Ранее: `tools/test_titd_acx.py` с указанными внешними исходниками: 13 сценариев успешно;
  с `--loader-patch`: 13, включая FF tail. В обоих стендах DE после Read намеренно произвольный.
- Реальные BIOS check/sender собраны sjasmplus без ошибок и исполнены в Z80.

Во втором ревью диагностика дополнена восстановлением HOLD. При последующей
проверке исправлен адрес ScreenPosition с 00h на 1Fh по исходникам BIOS;
модель CMOS теперь различает секунды и положение. Загрузчик TITD
и формат ACX не менялись. Прежние тесты упаковки/передачи ACX не проверяли
корректность последующей настройки HOLD.
Отдельный `tools/titdrev_hold.patch` исправляет адрес CMOS в доступном TITDREV;
`git apply --check` прошёл. Патч не применён во внешнем дереве, сборка и
аппаратная проверка игры с ним ещё не выполнены.
